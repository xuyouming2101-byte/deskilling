`deploy/postgres/aion/20260924_p61_p100.sql` extends the schedule check and claim
function to P100, adds 120 unopened schedule rows, and narrows all four formal
pool predicates to the selected AI condition. It checks the exact live function
fingerprints before deriving changes. Owners/grants, other functions, original
schedule rows, queues, responses, events, videos, and lesion metadata are verified
unchanged within the transaction. Reapplication fails closed rather than resetting
accounts. Existing queues are never rebuilt. Later-session ON queues block migration.

Back up and restore into a uniquely named test database before applying. Run
`tests/aion-integration.test.mjs` there as `deskilling_app`, never against canonical
research data. It preserves and resumes existing boundary queues, uses a new P61
only in the test database for submissions, and verifies all 100 participants'
Session 2/3 pools against synthetic OFF videos and ON distractors.

Only Test 1 videos existed at preflight. OFF-only routing does not make an
unconfigured Session 2/3 ready; the existing exact-40 readiness check still applies.

Application change is limited to `isStudyParticipantId`. Player, intake, submission,
video signing, and delivery are unchanged. A separate AI-ON codec incompatibility
is not solved by this roster change: uploaded MPEG-4 Part 2 files fail in Chromium.
Any derived playback copies require separate approval and timeline validation;
the source videos must not be overwritten.
